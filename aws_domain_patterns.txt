## .aws TLD — the ENTIRE TLD is AWS-restricted, no enumeration needed.
## IANA root zone db (iana.org/domains/root/db/aws.html) lists the sponsoring org as
## "AWS Registry LLC" — .aws is a closed generic TLD; only Amazon can register under it.
## So any hostname ending in ".aws" is AWS-owned by definition — matching on the bare
## suffix ".aws" (or just checking the TLD) covers all of them, present and future,
## without needing a name list. ct-disco.py's tlds.py already includes 'aws' as a
## valid TLD, so its domain-extraction regex already captures *.aws hostnames; only
## the -k keyword filter needs to target ".aws" to surface them.
##

## Notes
# - "amazonaws.com" alone will dominate matches (regional API + S3 + ELB + Lambda URLs + many more
#   all live under it). If the goal is coverage, scanning for "amazonaws.com" and "cloudfront.net"
#   alone likely captures >90% of AWS-attributable certs.
# - ct-disco.py currently supports one keyword at a time (-k). To check all patterns in one pass,
#   either run multiple scans or extend the script to accept a list/regex of keywords.
# - This list identifies AWS *infrastructure* domains appearing as SANs in certs (i.e. companies'
#   own certs issued for their AWS-hosted subdomains, or AWS's own certs for its endpoints) — not
#   AWS account IDs or ARNs, which don't appear in certificate SANs at all.
